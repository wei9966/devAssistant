# AI 助手智能化优化方案

## 一、现状问题分析

### 1.1 已实现功能
- [x] Function Call 机制（任务管理、番茄钟、SQL 查询）
- [x] 多步操作串联（"创建任务并开始番茄钟"）
- [x] SQL 自动纠错重试（智能体模式，最多 10 次）
- [x] 智能润色决策（简单操作跳过 AI 润色）
- [x] 上下文记忆数据库表（ai_context_memory）
- [x] 记忆读取功能（build_memory_context_hint）
- [x] AI 生成报表（日报/周报由 AI 生成）

### 1.2 核心问题

#### 问题 1：上下文记忆只读不写（严重）
```
现状：extract_context_from_response 函数已定义，但从未被调用
影响：AI 无法学习和记忆用户的任何信息，跨会话记忆完全失效
```

#### 问题 2：缺乏自然语言时间解析
```
现状：用户说"明天"、"下周一"、"3天后"，AI 无法解析为具体日期
影响：创建任务时无法智能设置截止日期
```

#### 问题 3：无主动提醒能力
```
现状：AI 只能被动响应，不会主动提醒
影响：用户可能错过重要截止日期
```

#### 问题 4：对话连贯性不足
```
现状：虽然有操作上下文，但缺乏对话主题追踪
影响：用户需要重复说明背景信息
```

#### 问题 5：缺乏用户行为学习
```
现状：不记录用户的使用习惯
影响：无法提供个性化建议（如常用的番茄钟时长）
```

---

## 二、优化目标

### 2.1 核心目标
将 AI 助手从 **"执行指令的工具"** 升级为 **"会学习、会记忆、会主动的智能伙伴"**

### 2.2 量化指标
- 上下文记忆写入：每次有价值的对话后自动保存关键信息
- 时间解析：支持 20+ 种自然语言时间表达
- 主动提醒：临近截止日期的任务自动提醒
- 个性化：根据历史行为提供个性化建议

---

## 三、功能实现方案

### 3.1 Phase 1：上下文记忆写入集成（最高优先级）

**目标**：让 AI 真正能够学习和记忆

**实现内容**：

1. **在 ai_chat_commands.rs 中集成记忆写入**
   - 在 Function Call 执行成功后调用 `extract_context_from_response`
   - 将提取的上下文保存到数据库
   - 支持的记忆类型：
     - `entity`: 实体信息（项目名、任务名）
     - `preference`: 用户偏好（番茄钟时长、优先级偏好）
     - `fact`: 重要事实（截止日期、计划）

2. **优化记忆提取逻辑**
   - 从创建任务中提取项目关联
   - 从番茄钟使用中提取时长偏好
   - 从用户消息中提取重要日期和计划

3. **记忆清理机制**
   - 定期清理低重要性的过期记忆
   - 保留高重要性记忆（重要性 >= 5）

**涉及文件**：
- `src-tauri/src/commands/ai_chat_commands.rs`
- `src-tauri/src/services/ai_chat_service.rs`

---

### 3.2 Phase 2：自然语言时间解析

**目标**：让 AI 理解各种时间表达方式

**支持的时间表达**：

| 类型 | 示例 | 解析结果 |
|------|------|----------|
| 相对日期 | 今天、明天、后天、大后天 | 当前日期 +0/1/2/3 天 |
| 相对周 | 下周一、下下周五、这周日 | 计算到对应日期 |
| 相对时间 | 3天后、一周后、两个月后 | 当前 + 对应时间 |
| 具体日期 | 1月15号、下个月5号 | 解析为具体日期 |
| 模糊表达 | 月底、年底、月初 | 计算对应日期 |
| 特殊表达 | 周末、工作日 | 最近的周六/周一 |

**实现内容**：

1. **创建时间解析服务 `time_parser_service.rs`**
   - 正则匹配 + 规则引擎
   - 支持中文时间表达
   - 返回标准日期格式

2. **集成到 Function Call**
   - create_task 自动解析 due_date
   - 在系统提示词中告知 AI 可以使用自然语言时间

3. **智能时间推断**
   - "周五要交的报告" → 自动设置截止日期为本周五
   - "下周开会讨论" → 提取并记录日期事实

**涉及文件**：
- `src-tauri/src/services/time_parser_service.rs`（新建）
- `src-tauri/src/services/ai_functions_service.rs`
- `src-tauri/src/services/ai_chat_service.rs`

---

### 3.3 Phase 3：智能提醒系统

**目标**：AI 能主动提醒用户重要事项

**实现内容**：

1. **创建提醒检查服务**
   - 检查即将到期的任务（1天内、3天内）
   - 检查长时间未处理的高优先级任务
   - 检查记忆中的重要日期

2. **在对话开始时注入提醒**
   - 修改 `build_system_prompt`，注入待提醒事项
   - AI 可以自然地在回复中提及提醒

3. **提醒内容模板**
   ```
   【待办提醒】
   - 任务"完成报告"明天就要截止了，记得优先处理！
   - 高优先级任务"代码评审"已经 3 天没有进展了
   ```

**涉及文件**：
- `src-tauri/src/services/reminder_service.rs`（新建）
- `src-tauri/src/services/ai_chat_service.rs`

---

### 3.4 Phase 4：用户行为学习

**目标**：从用户行为中学习偏好，提供个性化服务

**学习内容**：

| 行为 | 学习内容 | 应用场景 |
|------|----------|----------|
| 番茄钟使用 | 常用时长（25/30/45分钟） | 默认建议时长 |
| 任务创建 | 常用优先级、常用标签 | 智能填充默认值 |
| 工作时间 | 活跃时间段 | 提醒时机选择 |
| 任务完成 | 平均完成周期 | 估算任务时间 |

**实现内容**：

1. **行为统计服务**
   - 统计番茄钟时长分布
   - 统计任务优先级分布
   - 统计活跃时间段

2. **偏好推断算法**
   - 基于频率的偏好推断
   - 偏好随时间衰减

3. **个性化建议**
   - 在创建任务时建议优先级
   - 在启动番茄钟时建议时长
   - 在系统提示词中注入用户偏好

**涉及文件**：
- `src-tauri/src/services/user_behavior_service.rs`（新建）
- `src-tauri/src/services/ai_chat_service.rs`

---

### 3.5 Phase 5：对话连贯性增强

**目标**：让 AI 更好地理解对话上下文

**实现内容**：

1. **对话主题追踪**
   - 识别当前对话主题（任务管理、效率分析、番茄钟等）
   - 在主题内保持上下文连贯

2. **代词解析增强**
   - 增强 "它"、"这个"、"那个任务" 的解析
   - 支持 "刚才创建的"、"上一个" 等引用

3. **对话历史摘要**
   - 长对话时生成摘要注入系统提示词
   - 保留关键信息，减少 Token 消耗

**涉及文件**：
- `src-tauri/src/services/ai_chat_service.rs`
- `src-tauri/src/commands/ai_chat_commands.rs`

## 四、实现优先级

```
Phase 1 (记忆写入) ──► Phase 2 (时间解析) ──► Phase 3 (智能提醒)
        │                     │                      │
    最高优先级              高优先级               中优先级
    修复核心缺陷           增强易用性             提升智能度
                                    │
                                    ▼
                    Phase 4 (行为学习) ──► Phase 5 (对话连贯)
                           │                      │
                        中优先级               低优先级
                       个性化服务             优化体验
```

**建议实现顺序**：Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5

## 五、预期效果

### 5.1 使用场景对比

**场景 1：创建任务**

优化前：
```
用户：帮我创建一个任务，下周五之前完成报告
AI：好的，已创建任务"完成报告"（没有截止日期）
```

优化后：
```
用户：帮我创建一个任务，下周五之前完成报告
AI：好的，已创建任务"完成报告"，截止日期设为 2024-01-19（下周五）。
    我记住了这个截止日期，会在临近时提醒你。
```

**场景 2：启动番茄钟**

优化前：
```
用户：开始番茄钟
AI：好的，已启动 25 分钟番茄钟
```

优化后：
```
用户：开始番茄钟
AI：好的！根据你的习惯，我启动了 30 分钟的番茄钟（你最近常用 30 分钟时长）。
    专注工作吧！
```

优化前：
```
用户：今天有什么要做的？
```

优化后：
```
用户：今天有什么要做的？
AI：早上好！提醒你一下：
    - 任务"提交周报"明天就要截止了，建议今天优先处理
    - 你有 5 个待办任务，其中 2 个是高优先级

    另外，根据上次对话，你说过今天要开始"新功能开发"，要现在创建这个任务吗？
```

## 六、技术实现细节

### 6.1 记忆写入集成点

```rust
// ai_chat_commands.rs 中执行 Function Call 成功后

// 1. 提取上下文
let contexts = AiChatService::extract_context_from_response(
    &user_message,
    Some(&function_call.name),
    &exec_result,
);

// 2. 保存到数据库
for (context_type, key, value, importance) in contexts {
    let _ = ContextMemoryService::save_context(
        &conn,
        &context_type,
        &key,
        &value,
        importance,
    );
}
```

### 6.2 时间解析服务接口

```rust
pub struct TimeParserService;

impl TimeParserService {
    /// 解析自然语言时间表达
    /// 返回 Option<NaiveDate>，解析失败返回 None
    pub fn parse_natural_time(text: &str) -> Option<NaiveDate>;

    /// 从文本中提取所有时间表达
    pub fn extract_time_expressions(text: &str) -> Vec<TimeExpression>;
}

pub struct TimeExpression {
    pub original: String,      // 原始文本
    pub parsed_date: NaiveDate, // 解析后的日期
    pub confidence: f32,       // 置信度 0-1
}
```

### 6.3 提醒服务接口

```rust
pub struct ReminderService;

impl ReminderService {
    /// 获取需要提醒的事项
    pub fn get_pending_reminders(conn: &Connection) -> Vec<Reminder>;

    /// 检查任务截止日期提醒
    pub fn check_deadline_reminders(conn: &Connection) -> Vec<Reminder>;

    /// 检查记忆中的重要日期
    pub fn check_memory_reminders(conn: &Connection) -> Vec<Reminder>;
}

pub struct Reminder {
    pub reminder_type: ReminderType,
    pub title: String,
    pub message: String,
    pub urgency: Urgency, // High, Medium, Low
    pub related_task_id: Option<i64>,
}
```

## 八、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 记忆数据过多 | 性能下降，Token 超限 | 限制注入数量，定期清理 |
| 时间解析不准确 | 截止日期设置错误 | 解析后让用户确认 |
| 提醒过于频繁 | 用户厌烦 | 合并提醒，限制频率 |
| 偏好推断错误 | 建议不准确 | 提供修改偏好的入口 |
