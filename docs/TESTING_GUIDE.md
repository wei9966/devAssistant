## 1. SQL剪贴板监控功能测试

### 测试目标
验证复制SQL语句到剪贴板后能否自动保存到数据库

### 前置条件
- 应用已启动
- 剪贴板监控服务已在后台运行

### 测试步骤

#### 测试用例1: 复制有效的SELECT语句
1. 复制以下SQL到剪贴板:
```sql
SELECT * FROM users WHERE id = 1
```
2. 等待3-5秒（监控间隔为2秒）
3. 导航到"SQL历史"页面
4. **预期结果**: 应看到刚才复制的SQL出现在列表中,来源显示为"clipboard"

#### 测试用例2: 复制有效的INSERT语句
1. 复制以下SQL到剪贴板:
```sql
INSERT INTO tasks (title, description) VALUES ('测试任务', '这是一个测试')
```
2. 等待3-5秒
3. 刷新SQL历史页面
4. **预期结果**: 新的INSERT语句应出现在列表顶部

#### 测试用例3: 复制无效文本（应被忽略）
1. 复制普通文本: "这不是SQL语句"
2. 等待3-5秒
3. 检查SQL历史页面
4. **预期结果**: 此文本不应出现在SQL历史中

#### 测试用例4: 复制重复的SQL
1. 再次复制测试用例1的SQL
2. 等待3-5秒
3. 检查SQL历史
4. **预期结果**: 应该有两条相同SQL的记录（时间戳不同）

### 验证检查点
- [ ] SELECT语句能被自动捕获
- [ ] INSERT语句能被自动捕获
- [ ] UPDATE/DELETE语句能被自动捕获
- [ ] 非SQL文本不会被保存
- [ ] 来源字段正确标记为"clipboard"
- [ ] 时间戳正确记录
- [ ] 后台监控不影响应用性能

### 调试提示
如果功能不工作,检查:
1. 后台控制台是否有"检测到 SQL:"的日志输出
2. 数据库文件路径是否正确
3. 剪贴板权限是否授予

## 2. 手动新增SQL功能测试

### 测试目标
验证用户可以通过UI手动添加SQL记录

### 测试步骤

#### 测试用例1: 添加有效SQL
1. 导航到"SQL历史"页面
2. 点击页面右上角的"新增SQL"按钮
3. 在弹出对话框中输入:
   - SQL内容: `SELECT id, name FROM products WHERE price > 100`
   - 来源标记: manual（或留空使用默认值）
4. 点击"保存"按钮
5. **预期结果**:
   - 显示"保存成功"提示
   - 对话框自动关闭
   - SQL列表刷新,新记录出现在顶部

#### 测试用例2: 验证表单验证
1. 点击"新增SQL"按钮
2. 输入少于5个字符的文本,如"SQL"
3. **预期结果**: "保存"按钮应该被禁用
4. 清空输入框
5. **预期结果**: "保存"按钮保持禁用状态

#### 测试用例3: 取消操作
1. 点击"新增SQL"按钮
2. 输入一些内容
3. 点击"取消"按钮
4. **预期结果**: 对话框关闭,SQL列表无变化

#### 测试用例4: 添加多行SQL
1. 点击"新增SQL"按钮
2. 输入复杂的多行SQL:
```sql
CREATE TABLE test_table (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)
```
3. 点击"保存"
4. **预期结果**: 多行SQL正确保存并显示

### 验证检查点
- [ ] 新增按钮可见且可点击
- [ ] 对话框正确打开/关闭
- [ ] 表单验证工作正常
- [ ] SQL内容正确保存
- [ ] 来源标记正确保存
- [ ] 列表自动刷新
- [ ] 成功/失败提示正常显示

## 3. 工作日志功能测试

### 测试目标
验证工作日志的保存、加载、删除功能

### 测试步骤

#### 测试用例1: 保存新日志
1. 导航到"工作日志"页面
2. 确保日期选择器选中今天
3. 在文本框中输入:
```
今日完成:
1. 实现了SQL剪贴板监控功能
2. 添加了手动新增SQL功能
3. 完成了工作日志前后端对接
```
4. 点击"保存"按钮
5. **预期结果**:
   - 显示"日志已保存"提示
   - 日志出现在下方"最近日志"列表中

#### 测试用例2: 更新现有日志
1. 在现有日志内容后追加新内容
2. 点击"保存"按钮
3. **预期结果**: 日志内容更新成功

#### 测试用例3: 切换日期查看不同日志
1. 点击日期选择器,选择昨天的日期
2. **预期结果**:
   - 文本框显示昨天的日志（如果有）
   - 如果没有则显示空白
3. 输入昨天的工作内容并保存
4. 切换回今天
5. **预期结果**: 今天的日志内容正确显示

#### 测试用例4: 查看最近日志列表
1. 保存多个不同日期的日志
2. 检查"最近日志"列表
3. **预期结果**:
   - 日志按日期倒序排列
   - 显示日期标签
   - 显示内容预览（截断为100字符）

#### 测试用例5: 从列表选择日志
1. 点击"最近日志"列表中某条记录的"查看"按钮
2. **预期结果**:
   - 日期选择器自动更新为该日志的日期
   - 文本框显示该日志的完整内容

#### 测试用例6: 删除日志
1. 选择一个有内容的日期
2. 点击"删除"按钮
3. 在确认对话框中点击"删除"
4. **预期结果**:
   - 显示"日志已删除"提示
   - 文本框清空
   - 日志从列表中移除

#### 测试用例7: 删除空日志（边界测试）
1. 选择一个没有日志的日期
2. **预期结果**: "删除"按钮应该被禁用

#### 测试用例8: 刷新功能
1. 点击"刷新"按钮
2. **预期结果**:
   - 显示"刷新成功"提示
   - 数据重新加载

#### 测试用例9: 空内容验证
1. 清空文本框
2. 点击"保存"按钮
3. **预期结果**: 显示"日志内容不能为空"警告

### 验证检查点
- [ ] 日期选择器工作正常
- [ ] 保存功能正确（新增和更新）
- [ ] 加载功能正确
- [ ] 删除功能正确
- [ ] 日期切换自动加载对应日志
- [ ] 最近日志列表正确显示
- [ ] 列表排序正确（最新的在前）
- [ ] 删除按钮状态控制正确
- [ ] 空内容验证工作
- [ ] 刷新功能正常

## 5. 集成测试场景

### 场景1: 完整的SQL工作流
1. 在外部工具（如DBeaver）中编写SQL查询
2. 复制SQL到剪贴板
3. 等待自动捕获
4. 按 `Ctrl+Shift+S` 打开SQL历史
5. 验证SQL已自动保存
6. 手动添加一条相关的SQL
7. 将SQL标记为收藏
8. **验证**: 完整的SQL管理流程顺畅

### 场景2: 完整的工作日志流程
1. 早上开始工作时,打开工作日志页面
2. 输入今日计划
3. 工作过程中多次更新日志
4. 下班前查看最近几天的日志
5. 对比昨天和今天的工作内容
6. **验证**: 日志记录和查看流程顺畅

## 性能测试

### 测试指标
1. **剪贴板监控CPU占用**: 应 < 1%
2. **内存占用**: 应用整体 < 100MB
3. **SQL保存响应时间**: < 100ms
4. **工作日志加载时间**: < 200ms
5. **全局快捷键响应时间**: < 500ms

### 性能监控方法
- 使用Windows任务管理器监控CPU和内存
- 在Rust代码中添加时间戳日志
- 使用浏览器DevTools的Performance面板

## 已知问题和限制

1. **剪贴板监控**:
   - 监控间隔为2秒,可能延迟最多2秒
   - 某些受保护的应用复制的内容可能无法读取

2. **全局快捷键**:
   - 某些系统级快捷键可能冲突
   - 需要应用持续运行才能工作

3. **工作日志**:
   - AI生成功能尚未实现（标记为TODO）
