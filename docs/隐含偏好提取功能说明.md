# AI 对话助手 - 隐含偏好提取功能说明

## 功能概述

`extract_implicit_preferences` 方法能够从用户的对话消息中智能识别和提取隐含的习惯、偏好和意图，让 AI 助手真正"理解"并"记住"用户的工作模式。

## 实现位置

文件：`src-tauri/src/services/ai_chat_service.rs`

### 核心方法

```rust
pub fn extract_implicit_preferences(
    user_message: &str,
) -> Vec<(String, String, serde_json::Value, i32)>
```

### 集成点

在 `extract_context_from_response` 方法中自动调用，每次用户发送消息时都会执行隐含偏好提取。

## 支持的识别类型

### 1. 时间偏好识别

**识别模式：**
- "我一般/习惯/通常/喜欢 + 时间段"
- "时间段 + 效率高/习惯/喜欢/适合"

**示例：**

| 用户输入 | 提取结果 | 重要性 |
|---------|----------|--------|
| "我一般下午效率高" | time_preference: "下午" | 8 |
| "早上习惯先处理邮件" | time_preference: "早上" | 8 |
| "我喜欢晚上写代码" | time_preference: "晚上" | 7 |
| "下午效率最高" | time_preference: "下午" | 6 |

**保存的数据结构：**
```json
{
  "time_period": "下午",
  "pattern": "efficiency_or_habit",
  "original_message": "我一般下午效率高",
  "extracted_at": "2025-12-29 10:00:00"
}
```

### 2. 工作模式偏好识别

**识别模式：**
- "番茄钟/专注/工作 + 数字 + 分钟/小时"
- "我习惯/喜欢/用 + 番茄钟/分块/集中/专注"
- "一个番茄钟 + 数字"

**示例：**

| 用户输入 | 提取结果 | 重要性 |
|---------|----------|--------|
| "我习惯用番茄钟" | work_method_preference: "番茄钟" | 7 |
| "我一般一个番茄钟25分钟" | pomodoro_duration_preference: 25分钟 | 7 |
| "我喜欢把任务分成小块" | work_method_preference: "分块" | 7 |
| "专注工作30分钟" | pomodoro_duration_preference: 30分钟 | 6 |

**保存的数据结构：**
```json
{
  "method": "番茄钟",
  "duration_minutes": 25,
  "original_message": "我一般一个番茄钟25分钟",
  "extracted_at": "2025-12-29 10:00:00"
}
```

### 3. 优先级表达识别

**识别模式：**
- "很/非常/特别/超级 + 重要" 或 "必须/紧急/急"
- "不着急/不急/慢慢来/有空再/随时/随便"
- "今天/今日 + 必须/一定要" 或 "必须 + 今天/今日"

**示例：**

| 用户输入 | 提取结果 | 重要性 |
|---------|----------|--------|
| "这个很重要" | current_task_priority: "high" | 8 |
| "不着急，慢慢来" | current_task_priority: "low" | 5 |
| "必须今天完成" | current_task_priority: "urgent" | 9 |
| "特别紧急" | current_task_priority: "high" | 8 |

**保存的数据结构：**
```json
{
  "priority_level": "high",
  "priority_expression": "很重要",
  "original_message": "这个很重要",
  "extracted_at": "2025-12-29 10:00:00"
}
```

### 4. 项目关联识别

**识别模式：**
- "这是 + 项目名 + 项目"
- "项目名 + 项目 + 相关/有关/的"
- "和上次/之前/刚才 + 任务/项目"

**示例：**

| 用户输入 | 提取结果 | 重要性 |
|---------|----------|--------|
| "这是XXX项目的任务" | task_project: "XXX" | 8 |
| "YYY项目相关" | task_project: "YYY" | 6 |
| "和上次那个任务有关" | task_project: (关联) | 7 |

**保存的数据结构：**
```json
{
  "project_name": "XXX",
  "association_type": "current_task",
  "original_message": "这是XXX项目的任务",
  "extracted_at": "2025-12-29 10:00:00"
}
```

## 重要性评分规则

| 评分 | 说明 | 示例 |
|------|------|------|
| 9-10 | 紧急/必须完成的事项 | "必须今天完成" |
| 7-8 | 明确表达的习惯/偏好 | "我习惯..."、"我一般..." |
| 5-6 | 隐含的偏好/一般表达 | "效率高"、"适合" |
| 3-4 | 临时性表达 | "这次..."、"现在..." |
| 1-2 | 低优先级提示 | "不着急"、"随便" |

## 技术实现细节

### 正则表达式模式

使用 `Lazy` 静态初始化的正则表达式，提高性能：

```rust
static TIME_PREFERENCE_PATTERNS: Lazy<Vec<Regex>> = Lazy::new(|| {
    vec![
        Regex::new(r"我(一般|习惯|通常|喜欢).{0,15}(早上|上午|中午|下午|晚上|深夜)").unwrap(),
        Regex::new(r"(早上|上午|中午|下午|晚上|深夜).{0,10}(效率高|效率最高|习惯|喜欢|适合)").unwrap(),
    ]
});
```

### 日志记录

每次成功提取偏好时，都会记录详细日志：

```
[Context Memory] 提取到时间偏好: 下午 (重要性: 8)
[Context Memory] 提取到工作模式偏好: 番茄钟 (时长: Some(25), 重要性: 7)
[Context Memory] 提取到优先级表达: high (重要性: 8)
[Context Memory] 提取到项目关联: XXX (重要性: 8)
```

### 边界情况处理

1. **重复识别防护**：每种类型只提取第一个匹配项
2. **空值过滤**：自动跳过空字符串和无效数据
3. **关键词排除**：排除常见的非实体词（如"上次"、"之前"等）
4. **长度限制**：项目名等限制在合理长度内（1-20字符）

## 与现有功能的集成

### 自动调用流程

```
用户发送消息
    ↓
ai_assistant_chat 接收消息
    ↓
执行 Function Call
    ↓
extract_context_from_response
    ↓
extract_implicit_preferences（新增）
    ↓
保存到 context_memory 数据库
    ↓
后续对话可以利用这些偏好
```

### 数据库存储

提取的偏好会保存到 `context_memory` 表：

```sql
CREATE TABLE context_memory (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    context_type TEXT NOT NULL,  -- 'preference' 或 'entity'
    context_key TEXT NOT NULL,   -- 如 'time_preference'
    context_value TEXT NOT NULL, -- JSON 格式的详细信息
    importance INTEGER DEFAULT 5,
    created_at TEXT DEFAULT (datetime('now', 'localtime')),
    updated_at TEXT DEFAULT (datetime('now', 'localtime')),
    last_accessed_at TEXT DEFAULT (datetime('now', 'localtime')),
    access_count INTEGER DEFAULT 1
);
```

## 性能考虑

1. **正则表达式优化**：使用 `Lazy` 静态初始化，避免重复编译
2. **早期退出**：每种类型只提取第一个匹配项，避免过度处理
3. **最小化数据库操作**：批量保存上下文记忆
4. **日志级别控制**：使用 `log::info!` 可通过环境变量控制

## 注意事项

1. **隐私考虑**：所有提取的偏好都存储在本地数据库，不会上传到云端
2. **可撤销性**：用户可以通过清除上下文记忆来删除保存的偏好
3. **渐进式学习**：重要性评分确保频繁使用的偏好权重更高
4. **避免误判**：使用明确的正则模式和关键词排除，减少误识别
